# MoneyTrail synthetic payment-investigation records

All organizations, payments, records, contractual terms, and amendments are synthetic. No customer data or downloaded benchmark assets are included. Fixed seed 104 reproduces the sender's 1,200 background transactions. Each of the three demonstration cases has independent evidence IDs and an internally consistent USD payment trail dated October 9, 2026.

## Contents and provenance

`backend.data.generate(root)` writes separate SQLite stores for sender, processor, and recipient. Rows include a source ID, scenario, payment reference, and JSON evidence. Only the sender has background history. Records and amounts are generated by code. Narrative documents are templates, not authentic contracts. Separate evaluator ground truth describes the injected error; runtime services must not mount it.

The incorrect scenario deducts $350 against a $35 fee; the valid scenario permits $350; the missing scenario omits the agreement. A signed synthetic amendment effective October 1 permits $350 and explicitly supersedes the base agreement. Authority and applicable fee fields are structured synthetic attestations. Deterministic verification of them does not establish language-model understanding of contracts.

## Pilot evaluation

`scripts/evaluate.py` builds 30 distinct fixture cases: five each of valid fees, incorrect fees, valid amendments, missing agreements, ambiguous references, and malicious document instructions. Payment principals differ from the demonstration. These are held out from the demo seed, not independently collected research data. Variation is deliberately limited and does not measure arbitrary prose generalization.

The report measures deterministic disposition/amount correctness, unsupported resolutions, unnecessary escalations, citation-ID existence, and verifier execution time. It explicitly leaves retrieval, model baselines, distributed-agent baselines, and end-to-end latency unmeasured. Citation-ID existence is not semantic entailment. No fine-tuning has been performed, and these fixtures must not be described as trained model performance.

## Limitations and intended use

Use for workflow development, demonstrations, and regression tests. Not suitable as evidence of real-bank reliability, legal interpretation, fraud detection, or production-grade authorization. Never treat a synthetic authority flag as proof of an authentic agreement. Container isolation and authenticated source responses require integration tests outside this dataset. No third-party dataset license is claimed or inherited; distribution remains under the repository's selected license.
